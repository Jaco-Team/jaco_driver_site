# Docker

Production-сборка остаётся Next.js standalone на Node.js 24 с пользователем
`1001:1001`. Серверный runtime не содержит npm/npx. Доступ извне проходит
через Nginx на хосте; приложение публикует `3225` только на loopback.

## Production через OpenBao

Текущий процесс описан в [развёртывании через OpenBao](./deployment-openbao.md).
GitHub Actions проверяет код и публикует образ по запросу контроллера.
Контроллер берёт конкретные версии конфигурации из OpenBao, проверяет
результаты CI и deploy metadata, затем развёртывает backend/frontend по digest.
Купленный wildcard передаётся отдельно в Nginx; ключ TLS недоступен приложению.

Все реальные env, включая публичные значения, находятся в OpenBao. Для
production используются отдельные пути `projects/driver/prod/frontend-build`
и `projects/driver/prod/frontend-runtime`. Первый содержит только разрешённые
браузерные `NEXT_PUBLIC_*`; второй — настройки серверного контейнера.

`NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — браузерный ключ JavaScript API онлайн-карт,
он требуется при сборке. `YANDEX_TILES_API_KEY` — серверный ключ Tiles API для
офлайн-подложки, он передаётся только запущенному контейнеру. Один ключ не
заменяет другой. Серверный ключ не должен попадать в `NEXT_PUBLIC_*`.

Ответ `503` от `POST /api/offline-map/session` с сообщением
«На сервере не настроен ключ Yandex Tiles API.» означает отсутствие или
недопустимую длину серверного ключа в runtime. Онлайн-карта при этом может
продолжать работать. Проверяйте выбранную runtime-версию в OpenBao и выпуск
нового релиза; повторная сборка с браузерным ключом не устраняет эту причину.

## Локальная разработка

Этот раздел описывает только существующий локальный Compose-сценарий.
Для обычного запуска сайта на компьютере Docker не обязателен: используйте
`npm run dev` или `npm run preview:offline` по [инструкции разработки](./development.md).

Текущий `docker-compose.yml` требует наличия приватного `.env.development`,
а `.env.development.local` подключает дополнительно, если он есть. Базовый
файл может быть пустым, если все локальные параметры заданы в
`.env.development.local`; без него Compose завершится ошибкой ещё до запуска
сайта. Оба файла исключены из Git: их наличие на другом компьютере не
гарантируется. Для этого dev-сценария не нужны production env или команды
развёртывания.

```bash
docker compose --profile dev up --build app-dev
```

Dev-сервис монтирует исходники и запускает `next dev`. Реальные локальные
настройки сохраняйте в приватном `.env.development.local` с учётом обязательного
базового файла выше; имена параметров
есть в [`.env.example`](../.env.example). Все `.env*` исключены из Docker build,
в том числе примеры. Для локальной production-сборки Compose должен получить
публичные build args из приватного локального файла или окружения запуска;
этот сценарий не заменяет контролируемый production-деплой.

Отдельный сервис `app` в текущем Compose требует `.env.production`
и допускает дополнительный `.env.production.local`. Он не участвует в запуске
`app-dev`, `npm run dev` или `npm run preview:offline`. Это описание существующей
конфигурации, а не инструкция менять боевое окружение; сам Compose в рамках
актуализации документации не изменялся.

При обращении из браузера к локальному backend подходит
`http://localhost:8080`. Для запросов из контейнера используйте имя backend
в Docker-сети или `http://host.docker.internal:8080`, если оно настроено на
вашей платформе. Для проверки офлайн-режима используйте production preview,
как описано в [проверках](./testing/README.md).
