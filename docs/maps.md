# Карты сайта

## Текущая реализация

На `/map_orders` основной экран — [`OrdersMapScreen.tsx`](../widgets/orders-map-screen/ui/OrdersMapScreen.tsx). Онлайн-карта заказов использует JavaScript API 2.1: этот вариант сохраняет работавшие на бесплатном ключе пробки. Светлая подложка не изменяется, а в тёмной теме фильтруется только растровая основа карты; метки, элементы управления и пробки остаются вне фильтра. Ключ `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` используется браузером во время загрузки API.

На онлайн-карте масштаб меняется вертикальным ползунком без отдельных кнопок,
как в приложении; он виден при включённой настройке масштаба. В светлой теме
бегунок и заполненная часть тёмные, в тёмной — светлые. Такие же размеры и цвета
использует собственный ползунок офлайн-карты. Кнопка пробок включает и выключает
провайдер `traffic.provider.Actual` API 2.1. Если модуль или провайдер недоступен,
показывается сообщение в нижней панели.

Карта маршрута в рекомендациях использует JavaScript API 2.1. Если маршрут недоступен, показывается прямая линия и предупреждение.

Офлайн-подложка — отдельный механизм: растровые тайлы Яндекса загружаются через Tiles API и показываются локальным MapLibre-рендерером из [`public/offline-map/`](../public/offline-map). Онлайн-карту не следует подменять этим рендерером при обычном входе на экран.
Координата круглой метки привязана к центру значка, а метки-булавки — к её нижнему концу. Одиночная метка сохраняет подпись, а группа заказов показывает круглый счётчик и по одной цветной точке на заказ. Показываются не больше трёх точек, а надпись `+N` указывает число скрытых; время каждого заказа открывается по нажатию.
В тёмной теме онлайн-подложка API 2.1 и офлайн-тайлы проходят через один и тот же CSS/SVG-фильтр: общая подложка затемняется, затем отдельно сглаживаются и окрашиваются дороги и осветляются подписи. Прежняя отдельная перекраска воды, парков и фона офлайн-тайлов удалена; исходные изображения в Cache Storage остаются пригодны для светлой темы. Рисунок тайлов API 2.1 и Tiles API может различаться, поэтому пиксельное совпадение не гарантируется.

## Сохранение области

Базовая офлайн-карта не скачивается после загрузки заказов автоматически. Пользователь вручную выбирает Самару или Тольятти и запускает скачивание в настройках. Если подходящий городской пакет не сохранён, офлайн-экран показывает список заказов вместо карты. Устаревшие автоматически сохранённые области прежней версии удаляются при проверке хранилища.

Выбор города, подписи действий и нижняя шторка подтверждения удаления согласованы
с мобильным приложением. В категории «У других курьеров» метки и цветные точки
списка используют поле `color` из Laravel API; в остальных категориях приоритет
остаётся у цвета статуса `point_color`.

Порядок блока настроек: город, примерный размер, статус или прогресс, кнопки.
Во время загрузки показываются только процент и полоса прогресса без технического
счётчика тайлов и скачанных мегабайт. Основные действия называются «Скачать»,
«Пауза», «Продолжить», «Обновить» и «Удалить». Для старого пакета уровней 10–14
используется дополнительное действие «Докачать». Удаление на мобильной ширине
подтверждается нижней шторкой с кнопками «Нет» и «Удалить»; содержание совпадает
с приложением.

Город считается сохранённым только после завершения скачивания всех его тайлов. Сохранённые заказы не означают, что карта уже готова. Кэш отдельный у каждого устройства и браузера: скачивание на ПК не сохраняет карту на телефоне.

## Карты Городов

В настройках есть отдельный раздел «Офлайн-карты» для Самары и Тольятти. Выбор города хранится только на устройстве, не меняет `point_id`, город аккаунта или фильтры заказов и не требует кнопки сохранения настроек. По умолчанию используется название города из доступных кафе с текущим `city_id`; резервный вариант — координаты кафе из заказов.

Рабочие прямоугольники города с запасом перечислены в [`offlineMapCities.ts`](../shared/config/offlineMapCities.ts); это не кадастровые границы. Пакет включает уровни тайлов 10–15: 8295 тайлов для Самары и 4697 для Тольятти. Оценка размера до скачивания — 40 КиБ на тайл (около 324 и 183 МиБ соответственно), реальный размер показывается по скачанным данным. При недостаточном доступном объёме хранилища загрузка не начинается. Для ранее сохранённых пакетов 10–14 кнопка «Докачать» добавляет слой 15, повторно используя свежие тайлы; предыдущая полная карта остаётся доступной до завершения загрузки.

## Подробные участки

После ручного скачивания базовой карты города онлайн-карта заказов автоматически сохраняет небольшие участки вокруг маркеров до уровня тайлов 19. После увеличения карты до уровня 16 и выше сохраняются также просмотренные участки, только до открытого масштаба. Без сохранённого городского пакета умная докачка не запускается. Планирование выполняется после остановки перемещения на 750 мс; за один проход берётся до 32 ближайших к центру ячеек. Просмотр города издалека не вызывает скачивание подробной карты всего города. GPS для этой загрузки не используется.

Участки привязаны к сетке уровня 16: один участок содержит до 85 тайлов уровней 16–19. Совпадающие участки и свежие тайлы переиспользуются. Подробный кэш ограничен 128 МиБ и 128 участками независимо от восьми базовых областей; старые участки вытесняются первыми. Чтобы список с большим количеством маркеров не вызывал бесконечное повторное скачивание вытесненных участков, в текущей вкладке они повторно загружаются не раньше чем через 10 минут. Срок хранения не превышает 29 дней. Загрузка прекращается при потере сети, выходе из аккаунта и начале ручного скачивания города; ошибки фонового докачивания не ломают основную карту.

Офлайн-рендерер накладывает только полностью сохранённые подробные участки поверх базовой карты и разрешает соответствующее увеличение (уровень камеры MapLibre на единицу меньше уровня тайла). Вне сохранённых участков увеличивается базовая подложка, без подмены координат тайлов. Номера подъездов и отдельные координаты входов этим механизмом не добавляются. Удаление города также удаляет связанные подробные участки. Сервер подписывает только небольшие ячейки в поддерживаемых городах; запрос произвольной большой области на слоях 16–19 запрещён.

Загрузка, пауза, продолжение, обновление и удаление не привязаны к странице настроек. Скачивание продолжает работать при переходах между страницами. Манифест незавершённого пакета хранится в `jaco_offline_city_downloads_v1`; сами тайлы сохраняются сразу и повторно используются после обрыва. Прерванная из-за сети или закрытия страницы загрузка возобновляется при доступной сети и авторизованной сессии. Ручная пауза требует кнопки «Продолжить». На iOS фоновая вкладка может быть остановлена браузером; постоянная работа в фоне не гарантируется.

Обновление перезапрашивает старые тайлы, сохраняя уже обновлённые при продолжении. Удаление сначала останавливает загрузку, затем очищает метаданные и только те тайлы, которые больше не нужны другим сохранённым или незавершённым областям. Частичный пакет не помечается «Доступна офлайн». При запуске проверяется наличие тайлов готовых городов, чтобы не оставлять статус готовности после очистки Cache Storage.

Сервер принимает `cityId: samara | tolyatti` в `POST /api/offline-map/session`. Для этих пакетов координаты и масштабы берутся только из серверного каталога, а лимит составляет 4000 тайлов. Произвольные области по-прежнему ограничены 1500 тайлами; проверка авторизации и ограничение частоты запросов остаются прежними. Ключ Tiles API не передаётся браузеру.

Офлайн-экран использует только вручную сохранённый город, содержащий центр текущего кафе. Карта другого города и прежняя автоматически сохранённая область не подставляются. Онлайн-экран продолжает использовать обычную карту Яндекса.

Срок хранения остаётся 29 дней, логотип и атрибуция сохраняются. Основание текущей политики кэша — [условия Яндекс Карт](https://www.yandex.ru/legal/maps_api/ru/), сведения о частоте запросов — [документация Tiles API](https://yandex.ru/maps-api/docs/tiles-api/index.html).

Серверный [`/api/offline-map/session`](../pages/api/offline-map/session.ts) проверяет Bearer-авторизацию через Laravel и разрешённую область; [`/api/offline-map/yandex-tile`](../pages/api/offline-map/yandex-tile.ts) отдаёт только тайлы этой области. Laravel предоставляет данные заказов и проверку пользователя, но не раздаёт тайлы. На карте нужно сохранять кликабельные логотип Яндекса и ссылку на условия использования; исходные ресурсы лежат в [`public/offline-map/`](../public/offline-map).

Фоновая загрузка использует четыре параллельных загрузчика с общим темпом не более десяти запросов в секунду. При HTTP 429 все загрузчики делают общую паузу по `Retry-After` (секунды или HTTP-дата); без заголовка пауза увеличивается при повторных отказах. Для каждого тайла допускается до пяти попыток. Сервер сохраняет собственный лимит 24 запроса в секунду на IP и передаёт `Retry-After` от Tiles API. Область помечается готовой только после сохранения всех тайлов; при окончательной ошибке остальные загрузчики останавливаются, а уже сохранённые тайлы используются при следующей попытке.

## Ключи

- `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — браузерный ключ онлайн-карты; `NEXT_PUBLIC_*` встраивается во время сборки.
- `YANDEX_TILES_API_KEY` — серверный ключ Tiles API для офлайн-тайлов; браузеру не передаётся и требуется во время работы сервера.

Секреты не коммитятся. Перед production-сборкой проверьте env и ограничения ключей по домену/источнику; схема передачи переменных описана в [Docker-инструкции](./docker.md).
Production Docker-сборка завершается ошибкой, если `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` не передан. В CI он берётся из одноимённого GitHub Actions secret или variable репозитория; secret имеет приоритет. Перед сборкой workflow проверяет наличие значения. Локальный `.env.production.local` не попадает в опубликованный образ сам по себе. Офлайн-карта зависит от `YANDEX_TILES_API_KEY`.
При автоматическом деплое `YANDEX_TILES_API_KEY` берётся из одноимённого repository Actions secret и передаётся в окружение frontend-контейнера через SSH и Compose. Создавать файл с Tiles-ключом на сервере вручную не требуется.

## Проверка карты перед выпуском

Ручной smoke онлайн- и офлайн-карт выполнен 7 октября 2026 года на сайте,
Android и iOS: скачивание, пауза, продолжение, удаление, отсутствие пакета,
категории заказов, цвета и геометрия маркеров, домик кафе и ползунок масштаба.
Автоматический прогон того же этапа: `lint`, `typecheck`, 64 набора / 315
Vitest-тестов, Prettier и production-сборка прошли. Тестами дополнительно
закреплены точный текст удаления карты, пустой список сохранённых заказов и
открытие заказа из офлайн-списка.
Перед production-выпуском повторить проверку на release-сборках. Пакет
`@pbe/react-yandex-maps` нужен онлайн-карте и маршруту рекомендаций. API 2.1 не
заменяет Tiles API и существующий офлайн-кэш.
