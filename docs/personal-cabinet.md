## 24.11.2026 — первый прототип сайта

Цель этапа — согласовать состав, порядок и внешний вид ЛК на сайте, затем
перенести согласованное решение в приложение. Первый вариант использовал
вымышленные данные и общую шапку сайта.

- Пункт «Личный кабинет» расположен после карты заказов в боковом меню.
  График, расчёт и статистика сохраняют свои пункты меню и адреса.
- Сверху профиль: ФИО, роль, выбранное кафе и круглая иконка человека для
  сценария без фото. Ниже рабочие переходы, документы и допуски, промокод
  с копированием и пример метки со ссылкой в настройки.
- Цвета берутся из светлой и тёмной тем «Курьеров». На телефоне одна колонка,
  на широком экране две. При крупном шрифте сетка возвращается в одну колонку.
- Документы, статус допуска, промокод и метка — примеры для просмотра формы.
  Они не загружаются из API, инструкции пока представлены текстом. Пример
  метки ещё не использует сохранённые настройки карты.
- Прототип открывается без входа только на localhost в dev с локальным прокси
  API. Рабочие ссылки ведут на существующие защищённые страницы, где для
  просмотра нужен вход.

Рабочий ЛК доступен после входа в обычном боковом меню сайта и напрямую
по адресу `/lk`. На сборках с включённым service worker после входа
сохраняются страница и статические файлы для открытия ЛК без сети.

## Локальный запуск

Если локальный Laravel уже слушает порт 8080, запускайте сайт так:

```bash
cd /Users/denis/Public/work/jaco_driver_site
NEXT_PUBLIC_API_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_API_URL=http://localhost:8080 \
NEXT_PUBLIC_MEDIA_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_API_PROXY=true npm run dev -- --hostname localhost
```

Войдите на [локальном сайте](http://localhost:3225/auth) под тестовым
курьером и откройте [ЛК](http://localhost:3225/lk) через меню или по ссылке.

### Офлайн-проверка на локальном API

Запустите сайт с service worker на отдельном порту, оставив Laravel с
проверенным подключением к тестовой БД на порту 8080.

```bash
cd /Users/denis/Public/work/jaco_driver_site
HOSTNAME=localhost PORT=3325 \
NEXT_PUBLIC_API_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_API_URL=http://localhost:8080 \
NEXT_PUBLIC_MEDIA_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_API_PROXY=true npm run preview:offline
```

На [localhost:3325](http://localhost:3325/auth) войдите под №2563 и откройте
«Личный кабинет». Раскройте «Профиль» и «Документы и допуски». В Chrome
DevTools на вкладке Network включите Offline и затем верните No throttling.
Заголовки раскрытых разделов сохраняются, данные возвращаются автоматически.
Затем вернитесь в список заказов, отключите сеть и откройте ЛК из меню.
ЛК открывается с общей офлайн-плашкой, именем из текущей сессии,
рабочими переходами и меткой. После входа браузер заранее сохраняет
страницу и её файлы тем же способом, что и для других офлайн-страниц.
Данные профиля, документы и промокоды загружаются из API после
восстановления сети. В preview доступен ЛК с входом. Макет без входа
по `?uiPreview=1` доступен в dev.

ФИО берётся из текущей сессии Laravel. В шапке профиля под должностью
показывается адрес кафе, закреплённого за действующей должностью в БД.
Если привязки нет, адрес отсутствует. Выбор рабочего кафе на сайте
продолжает определять доступность перехода в статистику через общий флаг меню.
Для №2563 ожидаются ФИО из образца и «Тольятти, Ленинградская 47».
Карточка «Профиль» раскрывается и показывает ФИО, должность, место
работы, дату регистрации и стаж по этой дате. Пустые поля пропускаются.
Кадровое кафе, должность, дату, стаж, фото, допуски, инструкции, форму
и промокоды сайт запрашивает через `GET /api/v1/cabinet`. Без фото
и при ошибке загрузки видна иконка человека. Пример метки отображается
в конце ЛК по сохранённым формату времени, оформлению и масштабу.
Образец использует личный цвет курьера из настроек, как в категории
«У других». Если цвет не сохранён, карта назначает его автоматически
по составу заказов. Тогда в ЛК показывается нейтральный образец.
Заголовок карточки — «Твоя метка на карте». Ссылка «Настройки» ведёт
на общую страницу настроек. При классическом оформлении размер стандартный.
Персональные данные ЛК не сохраняются в локальный кэш. При потере сети
видны ФИО из сессии, рабочие переходы, пример метки и заголовки раскрытых
разделов «Профиль» и «Документы и допуски». Под шапкой появляется общая
плашка «Нет подключения к интернету». После возврата сети ЛК заново
запрашивает данные и восстанавливает содержимое раскрытых разделов.

Макет по-прежнему открывается без входа: [ЛК с тестовыми данными](http://localhost:3225/lk?uiPreview=1).
Для сравнения: [светлая тема и шрифт 26](http://localhost:3225/lk?uiPreview=1&theme=light&font=26),
[тёмная тема и шрифт 26](http://localhost:3225/lk?uiPreview=1&theme=dark&font=26),
[без карточки статистики](http://localhost:3225/lk?uiPreview=1&statistics=0).
Параметры меняют вид макета и не сохраняются в аккаунте. Макет доступен
только в локальной разработке с прокси API.

## Подготовка реальных данных

Демо подходит для проверки внешнего вида. Чтобы проверить ответ ЛК на
данных из БД, используйте отдельного тестового курьера. Удалённый набор
офлайн-заказов не переиспользуется.

```bash
bash /Users/denis/Documents/ChatGPT/Driver/lk-test-courier.sh check
bash /Users/denis/Documents/ChatGPT/Driver/lk-test-courier.sh create ID_КАФЕ
```

`check` читает эффективную конфигурацию запущенного Sail на порту 8080,
сверяет `main` и `system` с тестовой инструкцией и только после совпадения
проверяет подключение и выводит ID активных кафе. `create` повторяет проверку
и создаёт только курьера с доступом к одному выбранному кафе.
Реквизиты сохраняются локально в `~/.driver-lk-test-courier.json`.

и `system`, получен список активных кафе. Для тестового курьера выбрано
кафе №3 (Матросова 32). Для подготовки ЛК создан тестовый курьер №2563.
