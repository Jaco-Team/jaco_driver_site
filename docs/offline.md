# Офлайн-режим

Сайт сохраняет снимки заказов, настроек и телефонов в `localStorage` через [`shared/lib/offline/cache.ts`](../shared/lib/offline/cache.ts). Эти данные позволяют открыть ранее загруженный список и карточки заказов без сети; это не источник новых или актуальных заказов. При выходе из аккаунта локальный снимок удаляется.

Фильтр статусов «Активных» сохраняется при обновлении заказов, переходах между
картой/списком/категориями и перезагрузке в том же аккаунте и кафе. Выход или
смена аккаунта, смена кафе и новый ИИ-подбор включают все четыре статуса и
закрывают модалку фильтра. Повторный выбор текущего кафе фильтр не сбрасывает.

Сброс настроек по умолчанию находится под «Сохранить» и требует подтверждения.
После подтверждения пресет сразу сохраняется обычным запросом, без отдельного
серверного метода. При ошибке или отмене сохранённые настройки и черновик не
заменяются; без сети сброс и его подтверждение неактивны. Сохранённый цвет курьера,
кафе, фильтр статусов и скачанные карты не сбрасываются.

Пресет общий с приложением: системная тема, второе оформление меток (цвет текста
по фактической теме), шрифт 16, размер значков 1,0, формат `norm`, отменённые заказы
30 минут, обновление 30 секунд, подсказки включены, ИИ/ползунок масштаба/центрирование
выключены. После успеха существующая ИИ-подборка очищается. Набор значений хранится
в `entities/settings/model/settingsDefaults.ts`.

Состояние связи отслеживает [`connectivity.store.ts`](../features/offline/model/connectivity.store.ts): события браузера `online`/`offline` и проверка `navigator.onLine` каждые 15 секунд. Показатель отражает доступность сети по данным браузера, но сам по себе не гарантирует доступность backend. В UI есть состояние «Нет интернета»; недоступные без сети операции должны быть отключены, без ложных сообщений об ошибке.

Service worker и ресурсы экранов используются для локального просмотра после успешной онлайн-загрузки. В `next dev` service worker отключён; для проверки используйте [`preview:offline`](./development.md). Кэшируются основные страницы и ресурсы карты, но данные, которые пользователь ни разу не загрузил, офлайн не появятся. Подробности подложки и сроки хранения тайлов — в [документе о карте](./maps.md).

Само скачивание города доступно и в `dev`: тайлы сохраняются напрямую в Cache Storage, без участия service worker. Ошибка «Backend недоступен. Загрузка карты не начата.» означает сбой проверки сессии через API, а не запрет скачивания в dev. Для переходов между страницами и перезагрузки без сети нужен `preview:offline`; он использует локальный env, как `dev`, но оставляет production-режим и service worker включённым по умолчанию.

Ожидание сети для страниц и ресурсов в service worker ограничено 15 секундами. При тайм-ауте страницы используется сохранённая копия или экран офлайн; сохранённые файлы `/_next/static/` с идентификатором сборки или хешем читаются сразу из кэша. Ошибка Cache Storage не должна отменять успешный ответ сети. Эти механизмы не устраняют недоступность самого домена при первом открытии сайта.

У проверки сессии `/api/v1/auth/me` в клиенте отдельный лимит:
45 секунд для API на `localhost` или `127.0.0.1`, 15 секунд для остальных
адресов. Лимит выбирается по адресу API, а не по `dev`/preview. С сохранённым
токеном сетевой сбой не сбрасывает сессию, а до завершения проверки отображается
состояние загрузки.

Перед скачиванием карты сервер сайта отдельно проверяет пользователя через
тот же Laravel endpoint, но ждёт не более 12 секунд. При сетевом сбое или
тайм-ауте `/api/offline-map/session` отвечает `502` с сообщением «Backend
недоступен. Загрузка карты не начата.». Этот лимит пока не менялся; корректный
env в preview не гарантирует успешное скачивание при медленном локальном API.

Обновление service worker проверяется при запуске, восстановлении сети, возвращении вкладки на экран и каждый час. Если регистрация не удалась без сети, она повторяется после подключения. Статические файлы читаются из Cache Storage независимо от `Vary: Accept-Encoding`; версия модуля в query-параметрах при этом учитывается. После деплоя перед проверкой офлайн-режима нужно открыть сайт с сетью и дождаться активации нового service worker. Старый worker может не поддерживать новые ресурсы даже при наличии сохранённых тайлов; очищать кэш карт для обновления не требуется.

При восстановлении связи экраны должны обновлять данные без принудительной перезагрузки и не оставлять устаревший снимок как свежий. Особенно проверяйте смену точки/категории заказов, список и карту, карточки, границы видимой области и повторную авторизацию. Практический набор сценариев — в [релизном чек-листе](./testing/release-checklist.md).

Экран карты заранее выполняет модуль офлайн-карты, пока интернет доступен, через [`offlineMapRuntime.ts`](../shared/lib/offline/offlineMapRuntime.ts). Сохранение файлов в Cache Storage само по себе не выполняет ES-модуль. Если область ещё не скачана или модуль недоступен, причина отображается в блоке списка заказов, без всплывающего перекрытия и технического стека; под списком оставлен запас для нижних переключателей.

Город можно заранее скачать в настройках независимо от фильтра кафе. Карты и незавершённые загрузки управляются через [`offlineMap.store.ts`](../entities/offline-map/model/offlineMap.store.ts), наблюдение за связью и восстановление загрузок — через [`useOfflineCityDownloads.ts`](../features/offline-map/model/useOfflineCityDownloads.ts). Карта хранится только в данном браузере; новые заказы, изменение их статуса и серверные действия без сети недоступны. На другом устройстве пакет нужно скачать отдельно.
